# 교사 대상 AI 활용 연수 강의안 (3시간)

Nov 24, 2026 · 

## 연수 개요

AI 입문 교사가 3시간 뒤 **ChatGPT로 자기 업무 도구 1개를 직접 만들어 가는 것**이 목표다. 개념(1교시) → 도구 지도(2교시) → 실습(3교시) 순서로, 실습 시간을 가장 길게 둔다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 고등학교 교사, AI 입문 수준 (ChatGPT를 가끔 써 본 정도) |
| 시수 | 3시간 = 50분 × 3교시 + 쉬는 시간 10분 × 2 |
| 실습 도구 | ChatGPT (무료 계정 가능, 유료면 Work·GPTs·Sites까지 체험) |
| 준비물 | 노트북, ChatGPT 계정(사전 가입 안내), 각자 업무 자료 1개(개인정보 지운 것) |
| 산출물 | ① 나만의 업무 프롬프트 1개 ② 맞춤형 GPT 또는 프로젝트 1개 ③ 수업용 미니 도구 시안 |

| 교시 | 시간 | 주제 | 활동 |
| --- | --- | --- | --- |
| 1교시 | 50분 | LLM 개념 + 필수 용어 | 강의 30분, 퀴즈·질문 20분 |
| 2교시 | 50분 | 상용 AI 지도, Chat/Work/Code, 스킬·MCP | 강의 25분, 업무↔AI 짝짓기 25분 |
| 3교시 | 50분 | 실습 프로젝트 3단계 + 학생 수업 적용 | 실습 40분, 공유 10분 |

> 사전 공지: 학생 이름·성적·상담 내용 등 개인정보는 실습에 넣지 않는다.

## 1교시 (가) LLM의 개념: 챗봇 → 워크플로우 → AI 에이전트

핵심 메시지: **능력은 같은 LLM이고, 달라지는 것은 ‘누가 다음 단계를 정하느냐’다.** 챗봇은 사람이, 워크플로우는 미리 짠 순서가, 에이전트는 AI가 스스로 정한다.

**LLM(대규모 언어 모델) 한 줄 설명**: 방대한 글을 학습해 ‘다음에 올 말’을 예측하는 모델. 그래서 그럴듯하게 틀릴 수 있다(환각).

| 구분 | 누가 다음 단계를 정하나 | 학교 예시 | ChatGPT에서 |
| --- | --- | --- | --- |
| 챗봇 | 사람이 매번 질문 | “수행평가 루브릭 초안 써줘” | 일반 채팅 |
| 워크플로우 | 미리 정한 순서(항상 같은 길) | 설문 응답 → 요약 → 가정통신문 초안 자동 생성 | 맞춤형 GPT, 예약 작업 |
| AI 에이전트 | AI가 목표를 보고 계획·도구 사용·수정 | “다음 주 현장체험학습 자료 조사해서 안내문과 체크리스트 만들어” | ChatGPT Work(에이전트), Codex |

**교사가 알아야 할 4가지 한계**

- 환각: 없는 출처·법령·통계를 지어낼 수 있다 → 공문·수치는 반드시 원문 확인
- 최신성: 학습 시점 이후 정보는 검색 기능을 켜야 반영
- 개인정보: 입력한 내용이 외부 서버로 간다 → 학생 실명·성적 금지
- 책임: 최종 판단과 서명은 교사가 한다

**현장 퀴즈(5분)**: “매주 금요일 주간학습안내를 같은 양식으로 만든다”는 챗봇·워크플로우·에이전트 중 무엇이 맞을까? (정답: 워크플로우)

## 1교시 (나) 필수 용어 정리

AI로 ‘무언가를 만들기’ 시작하면 아래 용어가 반드시 나온다. 비유는 ‘식당’으로 통일한다.

| 용어 | 뜻(한 줄) | 식당 비유 | 학교 예시 |
| --- | --- | --- | --- |
| 프론트엔드 | 사용자가 보고 누르는 화면 | 홀·메뉴판 | 퀴즈 웹페이지의 버튼·글자 |
| 백엔드 | 보이지 않는 곳에서 데이터를 처리·저장 | 주방 | 제출한 답을 채점·저장하는 부분 |
| 데이터베이스(DB) | 자료를 정리해 두는 저장소 | 창고·장부 | 제출 기록 표 |
| API | 프로그램끼리 요청·응답하는 약속된 창구 | 주문서 양식 | 웹페이지가 GPT에게 질문을 보내는 통로 |
| MVP | 핵심 기능만 넣은 최소 시제품 | 메뉴 하나로 개업해 반응 보기 | 문제 5개짜리 퀴즈로 먼저 수업해 보기 |
| PWA | 앱처럼 설치되는 웹페이지 | 배달 앱 없이 단골 버튼 | 폰 홈 화면에 추가하는 학급 알림장 |
| 배포 | 만든 것을 인터넷 주소로 공개 | 간판 달고 문 열기 | 링크를 학생에게 공유 |
| 프롬프트 | AI에게 주는 지시문 | 주문 | “고1 수준, 10문항, 표로” |
| 컨텍스트 | AI가 한 번에 참고하는 자료의 범위 | 주문 시 건네는 메모 | 체크한 교육과정 문서 |
| 토큰 | AI가 글을 세는 단위(사용량·비용 기준) | 주문량 | 긴 문서일수록 많이 소모 |

**요약 한 문장**: “MVP로 작게 만들고, 프론트엔드만으로 충분하면 백엔드 없이, 필요하면 PWA로 폰에 올린다.”

## 1교시 (나+) 용어 실전: 퀴즈 앱 하나 뜯어보기

학생이 퀴즈에서 **\[제출\] 버튼을 누른 0.5초 동안** 프론트엔드 → API → 백엔드 → 데이터베이스를 한 바퀴 돈다. 이 한 바퀴를 보여주면 네 용어가 한 번에 잡힌다.

**제출 버튼을 누르면 일어나는 일**

1. 프론트엔드(학생 폰 화면): 고른 답 ③을 읽는다.
2. API 요청: “1번 문제, 답 ③”을 정해진 양식(JSON)에 담아 서버 주소로 보낸다.
3. 백엔드(서버): 정답과 비교해 채점한다. 정답은 학생 화면에 없고 서버에만 있다(부정행위 방지).
4. 데이터베이스: “언제, 몇 번, 무슨 답, 맞았는지”를 한 줄 저장한다.
5. API 응답: “오답, 힌트: …”를 돌려보낸다.
6. 프론트엔드: 화면에 힌트를 띄운다. 교사는 나중에 DB를 보고 오답률이 높은 문항을 찾는다.

**① 프론트엔드 — 학생이 보는 화면 (HTML + 자바스크립트)**

```html
<p>1. 온실가스가 아닌 것은?</p>
<label><input type="radio" name="q1" value="3"> ③ 산소</label>
<button id="submit">제출</button>
<script>
  submit.onclick = async () => {
    const answer = document.querySelector('input[name=q1]:checked').value;
    const res = await fetch('/api/submit', {          // ② API 호출
      method: 'POST',
      body: JSON.stringify({ question: 1, answer })
    });
    const result = await res.json();
    alert(result.correct ? '정답!' : '힌트: ' + result.hint);
  };
</script>
```

**② API — 오가는 주문서(요청과 응답)**

```json
요청  POST /api/submit   { "question": 1, "answer": "3" }
응답  200 OK             { "correct": true, "hint": "" }
```

**③ 백엔드 — 보이지 않는 주방 (서버 함수 예)**

```javascript
const ANSWERS = { 1: '3', 2: '1' };          // 정답은 서버에만
export default async (req) => {
  const { question, answer } = await req.json();
  const correct = ANSWERS[question] === answer;
  await db.insert('submissions', { question, answer, correct, at: new Date() }); // ④ DB 저장
  return Response.json({ correct, hint: correct ? '' : '광합성에서 나오는 기체를 떠올려 보세요' });
};
```

**④ 데이터베이스 — 저장된 장부(submissions 표)**

| id | question | answer | correct | at |
| --- | --- | --- | --- | --- |
| 101 | 1 | 3 | true | 2026-11-24 09:12 |
| 102 | 1 | 2 | false | 2026-11-24 09:12 |
| 103 | 2 | 1 | true | 2026-11-24 09:13 |

**실제로 이미 쓰고 있는 API 예시 — 나이스 급식 식단**

교육청 나이스 교육정보 개방 포털(open.neis.go.kr)은 급식 식단·학사일정·시간표를 API로 준다. 주소에 학교 코드와 날짜를 넣으면 그날 메뉴가 JSON으로 온다. 실제로는 포털에서 인증키를 발급받아 KEY=인증키를 붙이고, 연수 전 실제 호출로 확인한다. “오늘 급식 알려주는 학급 페이지”가 바로 이 API를 부르는 프론트엔드다.

```text
https://open.neis.go.kr/hub/mealServiceDietInfo?Type=json
  &ATPT_OFCDC_SC_CODE=[교육청코드]&SD_SCHUL_CODE=[학교코드]&MLSV_YMD=20261124
```

**만들 때 고르는 법(현장 판단)**

| 필요한 것 | 구성 | ChatGPT에서 |
| --- | --- | --- |
| 보여주기만(안내 페이지, 자가 채점 퀴즈) | 프론트엔드만 | 캔버스 HTML 파일 |
| 기록을 모아야(제출, 투표, 설문) | 프론트 + 백엔드 + DB | Sites(저장·DB 지원) |
| 다른 서비스 자료를 가져와야(급식, 날씨) | 프론트 + 외부 API | Sites 또는 Codex |

교사가 코드를 직접 쓸 필요는 없다. 다만 “제출 기록을 저장해줘(=DB)”, “정답은 서버에만 둬(=백엔드)”처럼 **용어로 요청할 수 있으면 결과물 품질이 달라진다**.

## 2교시 (다) 상용 AI 지도와 Chat / Work / Code

2026년 현재 주요 AI는 모두 **‘대화(Chat) · 일 맡기기(Work) · 코딩(Code)’ 3층 구조**로 수렴했다. ChatGPT도 2026년 7월 ChatGPT Work를 내놓으며 Chat·Work·Codex를 한 앱에 묶었다([OpenAI 발표](https://openai.com/index/chatgpt-for-your-most-ambitious-work)).

| 층 | 한 줄 정의 | 결과물 | 교사가 할 수 있는 일 |
| --- | --- | --- | --- |
| Chat | 묻고 답하기 | 답변·초안 텍스트 | 발문 아이디어, 가정통신문 초안, 개념 설명 |
| Work | 목표를 주고 맡기기(에이전트) | 파일: 문서·슬라이드·표·웹페이지 | 여러 자료 모아 수업 슬라이드, 평가 결과 표 정리, 행사 안내 사이트 |
| Code | 코드를 짜고 실행·배포 | 동작하는 프로그램 | 퀴즈 앱, 자리배치 도구, 학급 PWA |

| 서비스 | Chat | Work(에이전트) | Code | 학교에서 강점 |
| --- | --- | --- | --- | --- |
| [ChatGPT](https://openai.com/index/chatgpt-for-your-most-ambitious-work) | ChatGPT 채팅, GPTs, 프로젝트 | ChatGPT Work, Sites(베타) | Codex | 사용자 많음, 교사용 플러그인 등장 |
| [Claude](https://claude.com/docs/cowork) | Claude 채팅 | Cowork | Claude Code | 긴 문서 읽기·글쓰기, 스킬·MCP 원조 |
| Gemini | Gemini 앱, NotebookLM | Workspace 연동 에이전트 | 코딩 도구 | 구글 클래스룸·드라이브 연동 |
| Microsoft Copilot | Copilot 채팅 | M365(워드·엑셀·파워포인트) 안 | GitHub Copilot | 한글 외 오피스 문서 업무 |
| Perplexity | 검색형 채팅 | — | — | 출처 달린 조사 |

**시연 예시(같은 요청, 3층 비교)**: “기후변화 단원 평가를 도와줘”

1. Chat: 문항 10개 초안을 텍스트로 받는다.
2. Work: 문항·정답표·루브릭이 든 문서 파일을 받는다.
3. Code: 학생이 풀고 바로 채점되는 퀴즈 웹페이지를 받는다.

참고: 기능·요금제별 제공 범위는 자주 바뀜다. 연수 전날 실제 화면으로 다시 확인한다.

## 2교시 (다-1) ChatGPT Work 자세히

ChatGPT Work는 **목표를 주면 스스로 단계를 나눠 자료를 모으고, 문서·슬라이드·시트·사이트 같은 완성물을 내는 에이전트**다. 2026년 7월 9일 출시, Codex 기술 기반이며 몇 시간짜리 작업도 이어서 한다([OpenAI](https://openai.com/index/chatgpt-for-your-most-ambitious-work)).

| 항목 | 내용 |
| --- | --- |
| 어디서 | 웹·모바일의 Work, 데스크톱 앱의 Work 탭(Chat·Work·Codex 중 선택) |
| 누가 | 웹·모바일: Pro·Enterprise·Edu 우선, 이어 Plus·Business / 데스크톱 앱: Free 포함 전 요금제(사용량 한도 다름) |
| 자료 연결 | 플러그인(구글 드라이브, 메일, 캘린더, 팀즈 등). 프롬프트에 @앱이름으로 지정 |
| 사람의 역할 | 진행 상황 보기, 질문에 답하기, 방향 바꾸기, 중요한 동작(발송·수정) 승인 |
| 예약 작업 | 한 번 / 반복 / 이벤트 발생 시 / 변화 감시. 예: 매주 금요일 오후 주간학습안내 초안 |

**실제 작업에서는 이렇게 돌아간다 — “현장체험학습 준비” 예시**

요청: “@Google Drive의 ‘현장체험 계획서’를 읽고, 가정통신문·학생 안전 체크리스트·당일 시간표 슬라이드를 만들어 줘. 발송은 하지 말고 초안만.”

1. **계획** — 화면에 할 일 4개를 적는다: 계획서 찾기 → 핵심 정보 뽑기 → 문서 2개 → 슬라이드 1개.
2. **플러그인 호출** — 드라이브에서 ‘현장체험’ 검색 → 파일 2개 발견 → 내용 읽기(날짜·장소·인솔·비용).
3. **모르는 것은 묻기** — “계획서에 집합 시각이 두 개입니다. 8:30과 8:50 중 무엇인가요?”
4. **산출물 생성** — 가정통신문(문서), 체크리스트(표), 시간표(슬라이드) 파일을 만든다.
5. **스스로 점검** — 날짜·금액이 계획서와 같은지 대조한다.
6. **승인 대기** — 드라이브에 저장하거나 메일을 보내기 전에 “저장할까요?”를 묻는다.

**Chat과 Work, 같은 요청의 차이**

|  | Chat | Work |
| --- | --- | --- |
| 입력 | 교사가 내용을 붙여 넣음 | @드라이브에서 직접 찾아 읽음 |
| 과정 | 한 번에 답 | 계획 → 실행 → 점검, 중간 질문 |
| 결과 | 채팅 텍스트 | 문서·표·슬라이드 파일 3개 |
| 시간 | 수십 초 | 수 분\~수십 분 |

**학교 업무 시나리오 (프롬프트 그대로 사용)**

- “업로드한 수행평가 계획서로 루브릭 표, 학생용 안내문, 채점 시트 템플릿을 만들어 줘.”
- “설문 결과 엑셀을 분석해 학부모 설명회용 슬라이드 8장으로 정리해 줘. 그래프 포함.”
- “매주 금요일 15시에 @Google Drive의 다음 주 학사 일정을 읽고 주간학습안내 초안을 만들어 두어”(예약 작업).

주의: 학교 계정을 연결하면 Work가 그 안의 자료를 읽는다. 학생 개인정보가 담긴 폴더는 연결 범위에서 뺀다.

## 2교시 (다-2) ChatGPT Sites 자세히

Sites는 **말로 설명하면 웹사이트·가벼운 앱을 만들고, 주소(URL)까지 발급해 주는 기능**이다. 호스팅·접근 권한·저장소·데이터베이스가 포함돼 있어, 1교시의 ‘프론트 + 백엔드 + DB + 배포’를 한 번에 처리한다([도움말](https://help.openai.com/en/articles/20001339), [OpenAI Academy](https://openai.com/academy/chatgpt-sites)).

| 항목 | 내용 |
| --- | --- |
| 상태 | 공개 베타. Free·Go를 제외한 유료 요금제, 요금제별 사용량 한도 있음 |
| 만드는 곳 | 웹의 Work, 데스크톱 앱의 Work 또는 Codex. 프롬프트에 @Sites |
| 공개 범위 | 나만(기본) → 지정한 사람 → 워크스페이스 → 인터넷 누구나 |
| 주의 | 배포하는 주소는 모두 실제 운영 주소. 고칠 때는 버전 저장 → 확인 → 배포 순서 |

**만들기부터 공유까지 7단계**

1. Work를 열고 “@Sites …을 만들어 줘”라고 설명한다.
2. ChatGPT가 비공개 미리보기를 만든다.
3. 미리보기를 눌러 보며 테스트한다(폰 화면 포함).
4. “제출 버튼을 더 크게”처럼 한 가지씩 수정을 요청한다.
5. 배포(Deploy)하면 주소가 생긴다. 이때는 아직 나만 볼 수 있다.
6. 공유(Share)에서 공개 범위를 고른다. 학생용이면 링크 공개, 동료용이면 지정한 사람.
7. 동료에게 ‘편집 가능’ 권한을 주면 함께 고칠 수 있다(같은 워크스페이스).

**학교에서 바로 쓸 수 있는 Site 예시**

| Site | 프롬프트 예 | 쓰는 기능 |
| --- | --- | --- |
| 단원 형성평가 퀴즈 | “@Sites 이 문항 5개로 퀴즈 사이트, 문항별 오답률을 교사만 보게” | 프론트 + DB + 접근 권한 |
| 동아리 모집 페이지 | “동아리 소개, 활동 사진, 지원 양식이 있는 페이지” | 프론트 + 제출 저장 |
| 학급 알림판 | “주간 일정·준비물을 보여주는 학급 페이지, 내가 매주 수정” | 프론트 + 교사 편집 |
| 학생 투표·설문 | “체험학습 장소 3곳 투표, 결과는 막대그래프” | 프론트 + DB + 집계 |
| 교무실 업무 포털 | “학기 일정·양식 링크·담당자를 모은 내부 페이지” | 워크스페이스 한정 공개 |

**공개 전 체크**

- [ ] 학생 이름·성적·연락처가 화면이나 데이터에 없는가
- [ ] 학생 입력을 받는다면 무엇을 받고 누가 보는지 안내했는가
- [ ] 저작권 있는 사진·교과서 지문을 그대로 올리지 않았는가
- [ ] 공개 범위가 목적에 맞는가(인터넷 전체 공개는 마지막 선택)

연수 운영 팁: Free 계정 교사는 Sites가 없다. 3교시 3단계는 ‘캔버스 HTML’(무료)과 ‘Sites’(유료) 두 갈래로 안내한다.

## 2교시 (라) 스킬과 MCP

**스킬 = AI에게 주는 ‘업무 매뉴얼’, MCP = AI를 다른 프로그램에 꼽는 ‘표준 콘센트(USB-C)’.** 스킬은 ‘어떻게 할지’, MCP는 ‘무엇에 접근할지’를 담당한다.

| 구분 | 스킬(Skill) | MCP(Model Context Protocol) |
| --- | --- | --- |
| 비유 | 신규 교사용 업무 매뉴얼 | 노트북의 USB-C 단자 |
| 정체 | 지시문·예시·양식을 담은 폴더(SKILL.md) | AI와 외부 서비스를 잇는 공개 표준 |
| 역할 | 매번 설명할 필요 없이 같은 품질로 반복 | 구글 드라이브·캘린더·노션 등을 읽고 쓰기 |
| 학교 예시 | “우리 학교 가정통신문 양식·말투로 작성” | “드라이브의 수행평가 계획서를 읽고 캘린더에 일정 등록” |
| ChatGPT에서 | 스킬(Work·Codex에서 @로 호출) | 앱(예전 이름: 커넥터) |
| Claude에서 | 스킬 | 커넥터 |

- **플러그인** = 스킬 + 앱(MCP)을 한 꼾음으로 묶은 설치 단위. ChatGPT는 2026년 7월부터 플러그인 디렉터리로 제공한다([도움말](https://help.openai.com/en/articles/11487775-apps-in-chatgpt?gn=1)).
- MCP는 2024년 11월 Anthropic이 공개한 표준으로, ChatGPT·Claude·Copilot 등이 함께 쓴다. 한 번 만든 연결을 여러 AI에서 쓸 수 있다.
- 주의: 앱을 연결하면 AI가 그 계정의 자료에 접근한다. 학교 계정 연결은 학교 정보보안 지침을 먼저 확인한다.

**입문자용 체험**: 스킬을 직접 만들 필요는 없다. “방금 한 작업을 다음에도 쓸 수 있게 정리해줘”라고 하면 AI가 지침을 만들어 준다. 무료 계정이면 같은 원리를 맞춤형 GPT의 ‘지침’ 칸으로 체험한다.

## 2교시 (라-1) 스킬·플러그인·MCP 실제 적용하기

순서는 **① 플러그인 설치로 MCP(앱) 연결 → ② 스킬 만들기 → ③ 둘을 묶어 내 플러그인**이다. 입문 연수에서는 ①·②까지 시연하고 ③은 소개만 한다.

**세 가지를 한 표로 (ChatGPT 기준)**

|  | 맞춤형 GPT | 스킬 | 플러그인 |
| --- | --- | --- | --- |
| 무엇 | 목적별 ChatGPT 복제본 | 작업 절차서(SKILL.md) | 스킬 + 앱(MCP)을 묶은 설치 단위 |
| 부르는 법 | GPT를 골라 대화 | 관련 있으면 자동, 또는 @스킬명 | 자동, 또는 @플러그인명 |
| 어디서 쓰나 | 그 GPT 안에서만 | Chat·Work·Codex, 다른 AI(공개 표준) | Chat·Work·Codex |
| 교사 예 | ‘형성평가 출제 도우미’ | ‘가정통신문 작성’ | ‘구글 드라이브’, K–12 교사용 플러그인 |

### ① 플러그인 설치 = MCP 연결 (ChatGPT)

1. 사이드바 **Plugins** → “Google Drive” 검색.
2. 상세 화면에서 포함된 앱·스킬·필요 권한을 확인.
3. **설치 / 연결** → 구글 로그인 → 권한 허용.
4. 새 채팅에서 “@Google Drive 에서 2학기 평가 계획서 찾아 요약해 줘”.
5. 연결 해제는 설정 → Plugins(또는 앱)에서.

OpenAI 검증 배지(OpenAI Verified)가 있는 플러그인을 우선 쓴다. 플러그인 디렉터리는 모든 요금제에 보이지만 개별 설치 가능 여부는 요금제·지역에 따라 다르다([도움말](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt-and-codex)).

**MCP가 실제로 오가는 모습** — “@Google Calendar 다음 주 화요일 15시에 1학년 협의회 등록해 줘”

1. AI가 연결된 캘린더가 제공하는 도구 목록을 확인한다(일정 조회, 일정 만들기 …).
2. ‘일정 만들기’ 도구를 골라 아래 같은 요청을 만든다.
3. 쓰기 동작이다. 설정에 따라 실행 전에 승인을 묻거나 바로 실행한다(2026-11-25 연수 준비 중 확인: 승인 없이 바로 등록됨). 그래서 쓰기 권한은 신중히 허용한다.
4. 캘린더가 결과를 돌려주고, AI가 “등록했습니다”로 답한다.

```json
→ AI가 보내는 도구 호출  create_event { "title": "1학년 협의회", "start": "2026-12-01T15:00", "end": "2026-12-01T16:00" }
← 캘린더의 응답      { "status": "confirmed", "link": "https://calendar.google.com/..." }
```

1교시의 API와 같은 원리다. 차이는 **사람이 코드를 짜는 대신 AI가 어떤 도구를 언제 부를지 스스로 고른다**는 점이고, MCP는 그 도구 목록과 호출 방식을 표준으로 맞춘 규칙이다.

### ② 스킬 만들기 (ChatGPT)

1. 채팅에 “가정통신문 작성 스킬을 만들어 줘”라고 입력한다. 기본 포함된 skill-creator 스킬이 작동한다.
2. AI가 입력 항목·순서·말투·점검 기준을 물어본다. 예전 가정통신문 1–2개를 업로드하면 품질이 올라간다.
3. 만들어진 SKILL.md를 확인하고 설치한다.
4. 새 채팅에서 “12월 결업식 가정통신문 써 줘” → 스킬이 자동으로 쓰인다(또는 @스킬명).

개인 스킬은 Business·Enterprise·Edu 등 워크스페이스 요금제에서 바로 쓸 수 있고, 데스크톱 앱 Codex에서도 독립 스킬을 쓸 수 있다. 개인 Free·Plus·Pro 요금제에서는 채팅 속 개인 스킬을 쓸 수 없고, Enterprise·Edu는 관리자가 켜야 한다([OpenAI Academy](https://openai.com/academy/skills)).

**SKILL.md 실제 예시 — 폴더 하나가 스킬 하나**

```text
school-newsletter/
├── SKILL.md            ← 필수: 이름·설명·절차
├── assets/
│   └── template.docx   ← 우리 학교 양식
└── references/
    └── examples.md     ← 잘 쓴 가정통신문 2개
```

```markdown
---
name: school-newsletter
description: ○○고 가정통신문을 학교 양식과 공문체로 작성한다. "가정통신문", "학부모 안내" 요청에 사용.
---
# 가정통신문 작성

## 필요한 입력
- 행사명, 일시, 장소, 대상, 준비물, 회신 필요 여부

## 절차
1. 빠진 입력이 있으면 먼저 묻는다
2. assets/template.docx 양식을 따른다
3. 인사말 → 안내 본문 → 회신서 순서로 쓴다

## 말투
- "~하오니", "~바랍니다" 공문체, 한 문장 40자 이내

## 끝내기 전 점검
- 날짜와 요일이 맞는가
- 학생 개인정보가 없는가
```

스킬은 평소에 **이름과 설명만** AI가 알고 있다가, 요청이 설명과 맞으면 본문을 열어 그대로 따른다. 그래서 description에 ‘언제 쓰는지’를 분명히 적는 것이 핵심이다.

### ③ 더 나아가기

- **내 플러그인 만들기**: Plugins → + → Plugin Creator와 대화하며 스킬과 앱을 묶는다.
- **학교 자체 서비스 연결(커스텀 MCP)**: Business·Enterprise·Edu 워크스페이스에서 관리자가 MCP 서버 주소를 등록하고 게시한다([도움말](https://help.openai.com/articles/12584461)).
- **Claude에서 같은 일**: 설정 → 기능(Capabilities)에서 스킬 업로드, 설정 → 커넥터에서 MCP 연결. 같은 SKILL.md를 그대로 옮겨 쓸 수 있다(Agent Skills 공개 표준).

## 2교시 (라-2) 추천 스킬·MCP와 시연

교사에게 효과가 큰 것은 **구글 드라이브·캘린더 연결(MCP)과 ‘내 학교 양식’ 스킬**이다. 아래 목록에서 연수 당일 실제 화면으로 설치 가능 여부를 확인하고 3개만 시연한다.

**추천 MCP(앱·커넥터)**

| 이름 | 할 수 있는 일 | 교사 활용 예 | ChatGPT | Claude |

| Google Drive (문서·시트·슬라이드) | 파일 검색·읽기·만들기 | 평가 계획서 읽고 안내문 작성 | 플러그인 | 커넥터 |
| Google Calendar | 일정 조회·등록 | 학사 일정으로 주간학습안내 | 플러그인 | 커넥터 |
| Gmail | 메일 검색·초안 | 공문 메일 요약, 회신 초안 | 플러그인 | 커넥터 |

**추천 스킬**

| 스킬 | 무엇을 하나 | 구하는 곳 |
| --- | --- | --- |
| skill-creator | 대화로 새 스킬을 만들고 고침 | ChatGPT·Claude 기본 포함 |
| 문서 스킬(docx·pptx·xlsx·pdf) | 워드·파워포인트·엑셀·PDF를 양식대로 생성 | Claude 기본 포함, ChatGPT Work는 내장 기능 |

| 형성평가 출제(직접 제작) | 성취기준 표시 문항·해설·루브릭 | 3교시 2단계를 스킬로 변환 |
| 주간학습안내(직접 제작) | 학사 일정 → 고정 양식 안내문 | 캘린더 MCP와 함께 |
| K–12 교사용 플러그인(OpenAI) | 수업 자료·평가·교육과정 정렬 | ChatGPT Edu·ChatGPT for Teachers(미국 K–12 교사 대상) 배포 환경 한정([발표](https://openai.com/index/learn-teach-chatgpt-work-codex)) |

**연수 중 시연 3개 (각 3분)**

1. **드라이브 MCP** — “@Google Drive 에서 ‘2학기 지필평가 계획’ 찾아서 학생용 시험 범위 안내문 만들어 줘.” 볼 것: AI가 검색 → 읽기 → 작성하는 중간 기록.
2. **스킬** — 같은 프롬프트 “결업식 가정통신문 써 줘”를 스킬 없이 / 스킬 있이 비교. 볼 것: 양식·말투·빠진 정보 질문의 차이.
3. **Canva 연결** — “@Canva 과학의 날 행사 포스터 초안 3개.” 볼 것: 채팅 안에서 디자인이 만들어지고 Canva에서 이어서 편집.

준비: 시연용 구글 계정에 가상 평가 계획서 1개, 예전 가정통신문 2개를 미리 넣어 둔다(실제 학생 정보 없이).

## 활동: 학교 업무 ↔ 알맞은 AI 짝짓기

고르는 기준은 두 가지다. **결과물이 무엇인가(답변/파일/프로그램)**, 그리고 **어느 자료에 붙어 있나(구글/MS/웹)**. 아래 표의 ‘추천’ 열을 가리고 모둠별로 먼저 짝지어 본 뒤 공개한다(15분).

| 학교 업무 | 결과물 | 추천 층 | 추천 도구(예) | 이유 |
| --- | --- | --- | --- | --- |
| 가정통신문·안내문 초안 | 텍스트 | Chat | ChatGPT | 짧고 빠름 |
| 수업 발문·활동 아이디어 | 텍스트 | Chat | ChatGPT, Claude | 대화하며 다듬기 |
| 교과서·연수 자료 요약·질문 | 요약·답변 | Chat | NotebookLM | 올린 자료 안에서만 답함 |
| 최신 정책·진학 정보 조사 | 출처 달린 요약 | Chat(검색) | Perplexity, ChatGPT 검색 | 출처 확인 가능 |
| 수행평가 루브릭 + 평가지 파일 | 문서 파일 | Work | ChatGPT Work, Claude Cowork | 여러 단계를 한 번에 |
| 연수·수업 슬라이드 제작 | 슬라이드 | Work | ChatGPT Work, Claude, Gamma | 파일로 완성 |
| 엑셀 성적·설문 결과 정리 | 표·그래프 | Work | ChatGPT Work, Copilot in Excel | 표 계산 + 시각화 |
| 구글 클래스룸·드라이브 자료 정리 | 문서·폴더 | Work | Gemini(Workspace) | 자료가 구글에 있음 |
| 주간학습안내 매주 반복 | 같은 양식 문서 | Work + 스킬 | 맞춤형 GPT, 스킬 | 양식 고정 반복 |
| 학생용 퀴즈·단어장 웹앱 | 프로그램(링크) | Code | Codex, ChatGPT Sites, Claude Code | 학생이 직접 사용 |
| 동아리·학급 알림 PWA | 앱 | Code | Codex, Claude Code | 폰 설치형 |

**판단 흐름**: 답만 필요하면 Chat → 파일이 필요하면 Work → 학생이 직접 쓸 도구면 Code. 같은 일을 매주 하면 스킬·맞춤형 GPT로 고정한다.

## 고등학생과 LLM으로 수업한다면

원칙은 AI가 대신 해 주는 수업이 아니라 **AI의 답을 검증·비판하는 수업**이다. 평가는 결과물보다 과정(프롬프트 기록·수정 이유)에 비중을 둔다.

**수업 전 체크**

- [ ] 서비스 이용 연령 기준과 보호자 동의 필요 여부 확인(서비스별 약관)
- [ ] 학교·교육청의 생성형 AI 활용 지침 확인
- [ ] 개인 계정 대신 교사 시연·모둠 1계정·교육용 플랫폼 중 운영 방식 결정
- [ ] ‘AI 사용 표시’ 규칙 안내(어디에 어떻게 썼는지 적기)

| 교과 | 수업 아이디어 | AI 역할 | 학생이 하는 일 |
| --- | --- | --- | --- |
| 국어 | AI가 쓴 설득문 고쳐 쓰기 | 초안 제공 | 논지 오류 찾기, 근거 보강 |
| 영어 | AI와 역할극 대화 | 대화 상대 | 표현 기록, 틀린 말 피드백 비교 |
| 수학 | AI 풀이의 오류 찾기 | 일부러 틀릴 수 있는 풀이 | 단계별 검증 |
| 사회 | 같은 쟁점, 여러 AI 답 비교 | 관점 제시 | 편향·출처 검증 |
| 과학 | 가설 세우기·실험 설계 피드백 | 조언자 | 실험 후 AI 예측과 비교 |
| 정보 | 말로 웹앱 MVP 만들기 | 코드 생성 | 요구사항 작성, 테스트, 수정 요청 |
| 진로 | 직업 인터뷰 시뮬레이션 | 직업인 역할 | 질문 설계, 실제 자료와 대조 |

**1차시 수업 흐름 예(50분)**: 도입 5분(AI 한계 사례) → AI 사용 15분 → 검증·수정 20분 → 성찰 기록 10분(“AI가 틀린 점, 내가 바꾼 점”).

## 3교시 실습 프로젝트 3단계 (ChatGPT)

주제는 하나로 통일한다: **“내 과목 한 단원의 형성평가 도구 만들기”**. 같은 주제를 Chat → 맞춤형 GPT → 웹페이지로 키우며 3층 구조를 몸으로 익힌다.

| 단계 | 시간 | 목표 | 산출물 | 관련 개념 |
| --- | --- | --- | --- | --- |
| 1. 프롬프트 다듬기 | 12분 | 좋은 지시문의 5요소 익히기 | 문항 5개 + 해설 | Chat, 프롬프트 |
| 2. 나만의 GPT 만들기 | 15분 | 반복 업무를 ‘지침’으로 고정 | 맞춤형 GPT(또는 프로젝트) 1개 | 워크플로우, 스킬 개념 |
| 3. 미니 웹 도구(MVP) | 13분 | 학생이 푸는 퀴즈 페이지 | HTML 파일 1개 | Code, MVP, 프론트엔드 |

### 1단계: 프롬프트 다듬기 (Chat)

먼저 “평가 문제 만들어줘”만 입력해 결과를 본 뒤, 5요소(역할·대상·과제·조건·형식)를 넣어 비교한다.

```
너는 고등학교 [과목] 교사야. (역할)
고[학년] 학생, 학습 수준은 중간이야. (대상)
[단원명] 단원의 형성평가 문항 5개를 만들어 줘. (과제)
객관식 3개, 서술형 2개. 각 문항에 성취기준을 표시해. (조건)
표로: 번호 | 문항 | 정답 | 해설 | 성취기준 (형식)
```

확인 포인트: 정답·성취기준이 실제와 맞는지 교사가 검토한다(환각 체험).

### 2단계: 나만의 GPT 만들기 (워크플로우)

1. ChatGPT → GPT 탐색 → 만들기(유료) 또는 프로젝트 생성(무료 가능 범위 확인).
2. ‘지침’에 1단계 프롬프트를 고정 규칙으로 바꿔 넣는다(예: “항상 표 형식, 항상 성취기준 포함”).
3. 교육과정 성취기준 문서를 지식 파일로 올린다.
4. 단원명만 바꿔 2번 테스트 → 같은 품질이 나오는지 확인.

개념 연결: ‘매번 설명하지 않아도 되는 지침’이 곧 스킬의 출발점이다.

### 3단계: 미니 웹 도구로 (MVP)

```
위 문항 5개로 학생용 퀴즈 웹페이지를 만들어 줘.
- HTML 파일 하나로, 인터넷만 있으면 열리게
- 한 문제씩 보여주고, 제출하면 정답·해설 표시
- 끝에 점수 표시, 학생 이름은 받지 말 것
- 폰 화면에서도 보기 좋게
```

- ChatGPT의 캨버스·미리보기 또는 Sites(베타)로 확인한다. 다운로드한 HTML을 더블클릭해도 열린다.
- “오답이면 힌트를 먼저 보여줘”처럼 한 가지씩 수정 요청 → 반복 개선을 체험한다.
- 백엔드가 없으므로 점수는 저장되지 않는다 → ‘저장하려면 무엇이 필요할까?’로 1교시 용어와 연결.

**공유(10분)**: 2–3명이 화면을 보여 주고, “다음 주 내 수업에 쓸 한 가지”를 적어 낸다.

## 그 외 제안

입문자 3시간 연수의 성패는 **강의를 줄이고 ‘내 일에 바로 쓴 경험’을 남기는 것**에 달려 있다.

- **사전 설문(3문항)**: 사용 경험, 유료 계정 여부, ‘가장 줄이고 싶은 업무’ → 3교시 주제를 맞춤화
- **계정 사전 준비**: 당일 가입·인증에 10분 이상 사라진다. 연수 전날까지 로그인 확인
- **무료·유료 차이 대비**: 맞춤형 GPT 만들기·Work는 요금제에 따라 다르다 → 무료 계정용 대체 경로(프로젝트·긴 지침 복사 사용) 준비
- **짝 실습**: 입문자끼리 막히면 멈춘다. 숙련자 1명 + 입문자 1–2명으로 자리 배치
- **프롬프트 카드 배포**: 5요소 템플릿 + 업무별 예시 10개를 A4 한 장으로
- **윤리·보안 5분 고정**: 개인정보 미입력, 결과 검증, AI 사용 표시, 학교 계정 연동 전 확인
- **사후 과제**: 2주 뒤 ‘실제로 써본 사례 1개’ 공유 → 학교 내 활용 사례집으로 축적
- **후속 연수 제안**: 2차 연수에서 Work(에이전트)·스킬·MCP를 실제로 연결해 보기, 3차에서 PWA 배포까지

## 부록: Microsoft Copilot 활용법 (부산 PENZ 계정 기준)

부산 교사·학생은 2026년 9월부터 **PENZ(펜즈) 계정 하나로 Microsoft 365에 로그인**한다(교육디지털원패스 연계, 초1부터 고3까지 같은 계정). 이 부록은 PENZ가 Microsoft 365 교육용(A 라이선스) 계정이라는 전제로 쓴다. 학교 계정이라 추가 비용이 없고, 입력한 내용이 AI 학습에 쓰이지 않으며, 교육청이 학생 접근을 관리한다. 그래서 **학생 수업은 PENZ Copilot이 기본 선택**이다. 학생이 Copilot Chat을 쓰려면 교육청이 학생 계정에서 켜 둬야 한다. 유료 Microsoft 365 Copilot 라이선스 포함 여부는 공개 자료로 확인되지 않아, 아래 표의 ‘유료’ 항목은 연수 전 확인이 필요하다([노컷뉴스](https://nocutnews.co.kr/news/6554055), [아시아경제](https://view.asiae.co.kr/article/2026072809321747042)).

**에듀 계정(Microsoft 365 A1·A3·A5)으로 무료인 것 vs 유료인 것**

| --- | --- | --- | --- | --- |

연수 때 무료 범위와 유료 범위를 분명히 나눠 보여준다. “워드 안의 Copilot 버튼이 왜 안 되죠?”는 대부분 유료 라이선스 문제다.

### ① Copilot Chat — 학교 계정으로 쓰는 ChatGPT형 대화

웹 검색, 파일 업로드, 이미지 생성, Copilot Pages(대화 결과를 함께 고치는 문서), 에이전트를 쓴다. ChatGPT 무료 버전과 비슷하지만 학교 데이터 보호가 적용된다.

| 하고 싶은 일 | 이렇게 요청 | 나오는 것 |
| --- | --- | --- |
| 공문 요약 | PDF 공문을 올리고 “담임이 할 일·기한만 표로” | 할 일·기한·제출처 표 |
| 수업 삽화 | “열대우림 단면도를 교과서 삽화 느낌으로, 글자 없이” | 생성 이미지(수업 자료에 바로 삽입) |
| 최신 자료 조사 | “2026년 고교학점제 관련 교육부 발표 요약, 출처 링크 포함” | 요약 + 출처 링크(원문 확인 필수) |
| 동료와 초안 협업 | 답변을 Copilot Pages로 보내 공유 | 동료가 함께 고치는 문서 |

**수업 연결 — Teams 과제에 AI 활동 넣기**: Teams 교육용 과제에서 ‘Study and Learn 할당’ 또는 ‘Copilot 시작 프롬프트’를 넣을 수 있다(2026년 11월 전체 제공 예정 — 연수 당일 화면 확인). 예: 시작 프롬프트 “너는 내 설득문의 논리만 점검하는 코치야. 나대신 고쳐 쓰지 마.”를 과제에 붙이면 학생이 같은 규칙으로 시작한다([Microsoft EDU 2026년 10월](https://techcommunity.microsoft.com/blog/educationblog/whats-new-in-microsoft-edu-%E2%80%93-october-2026/4516290)).

### ② Teach — 교사 전용 수업 자료 공장

Copilot 앱 안의 교사 전용 화면이다. 빈 채팅창 대신 **과목·학년·언어·성취기준·시간을 고르는 양식**이 나와서, 프롬프트를 잘 몰라도 구성 요소가 빠지지 않는다. 결과는 워드·Forms로 저장하고 Teams 학급에 공유한다([Microsoft 지원](https://support.microsoft.com/en-US/education/teach-in-the-microsoft-365-copilot-app)).

| 메뉴 | 무엇을 만드나 | 결과 형태 |
| --- | --- | --- |
| 수업 계획(Lesson Plan) | 차시 수업 계획. 35개국 교육과정 기준 중 선택 또는 내 자료 첨부 | 워드 문서 |
| 단원 계획(Unit Plans) | 여러 차시를 묶은 단원 흐름(2026년 10월 말 전체 제공 목표, 연수 전 메뉴 확인) | 워드 문서 |
| 루브릭 | 평가 기준·수준별 서술(워드 문서로 저장) | 표 |
| 퀴즈 | 내 자료 기반 문항 | Microsoft Forms 퀴즈(바로 배포) |
| 학습 활동 | 플래시카드(힌트 포함). 빈칸 채우기 등은 순차 추가 | 학생용 활동 링크 |
| 콘텐츠 수정(Modify Content) | 기준 정렬 / 지시문 차별화 / 읽기 수준 조절 / 실생활 예시 추가 | 수정된 텍스트·문서 |

**실제 예시 1 — 수업 계획 만들기**

1. Teach → 수업 계획 선택.
2. 입력: 과목 ‘통합과학’, 학년 ‘고등학교 1학년’, 언어 ‘한국어’, 시간 ‘50분’, 내용 “기후변화와 에너지 전환, 모둠 토의 중심”.
3. 성취기준: 목록에 한국 교육과정이 없으면 **성취기준 문장을 직접 붙여 넣거나 문서를 첨부**한다.
4. 결과: 학습 목표 → 도입 → 전개(활동) → 정리 → 평가 구성의 초안. 워드로 저장.
5. 이어서 ‘이 수업으로 퀴즈 만들기’ → Forms 퀴즈 5문항 → Teams 과제로 배포.

**실제 예시 2 — 읽기 수준 조절 (전후 비교, 연수용 예시로 직접 작성)**

| 원문 | 기초 학력용 (핵심 용어 유지: 온실가스, 탄소중립) |
| --- | --- |
| 화석연료 연소 과정에서 배출되는 온실가스가 대기 중 누적됨에 따라 지표의 복사 평형이 교란되었으며, 이에 대응하기 위한 탄소중립 전략이 요구된다. | 석탄·석유를 태우면 **온실가스**가 나온다. 온실가스가 공기에 쌓이면 지구가 더워진다. 그래서 내보내는 양과 줄이는 양을 같게 만드는 **탄소중립**이 필요하다. |

사용법: Teach → 콘텐츠 수정 → 텍스트 붙여넣기(또는 워드·PDF 업로드) → ‘읽기 수준 수정’ → 학년·수준 선택 → **핵심 용어** 칸에 ‘온실가스, 탄소중립’을 넣어 쉬운 말로 바뀌지 않게 한다.

**나머지 수정 기능 활용 예**

- 지시문 차별화: “보고서를 작성하시오” → 단계별 체크리스트 버전(도움이 필요한 학생용)과 심화 과제 버전을 동시에.
- 실생활 예시 추가: ‘열의 전도’ 설명에 “뜨거운 국에 넣은 쇠숬가락이 뜨거워진다” 같은 예를 개수 지정해 추가.
- 기준 정렬: 기존 활동지를 올리고 어느 성취기준에 해당하는지 표시·보강.

한계: Teach 화면은 100개 이상 언어로 표시되지만, 한국 교육과정 기준 목록 제공 여부와 한국어 결과 품질은 연수 전 직접 확인해야 한다. 결과물은 초안이므로 사실·성취기준 일치를 교사가 검토한다.

### ③ Copilot Notebooks — 내 자료로만 답하는 지식방

자료(참고 항목)를 모아 두면 Copilot이 **그 자료를 근거로** 답하는 작업 공간이다. Google NotebookLM과 비슷한 개념이며, Copilot 앱의 앱 목록(와플 메뉴)에 있다. 교육용 A1·A3·A5 사용자는 추가 비용 없이 개요 페이지, 마인드맵, 학습 가이드를 쓴다(학생은 13세 이상) ([Microsoft 지원](https://support.microsoft.com/en-US/education/copilot/copilot-notebook-study-guide)).

**만들기 4단계**

1. Copilot 앱 → Notebooks → 새 노트북, 이름 짓기(예: “통합사회 2단원 시험 대비”).
2. 참고 항목 추가: 워드·파워포인트·PDF·엑셀·OneNote 페이지·Copilot Pages·Teams 회의 메모.
3. 개요 페이지에서 전체 요약·핵심 주제를 확인하고, 채팅으로 질문한다.
4. 참고 항목 창의 + → **학습 가이드** → 넣을 페이지 선택 → 생성.

**학습 가이드에 들어가는 것**

| 페이지 | 내용 |
| --- | --- |
| 요약 | 자료 전체 개요(항상 생성) |
| 주제 페이지 | 핵심 주제마다 심화 설명과 생각 질문 |
| 플래시카드 | 앞면 질문·용어, 뒷면 답 |
| 퀴즈 | Forms 기반 자기 테스트. **결과는 비공개**(교사 성적부로 안 감) |
| 빈칸 채우기·짝 맞추기 | 용어·개념 연습 |

제약: 참고 자료 합계가 약 10만 자를 넘거나 보안 라벨이 붙은 파일이 있으면 요약·주제 페이지만 만들어지고 플래시카드·빈칸·짝 맞추기 등 활동은 빠질 수 있다. 단원 단위로 나눠 만든다.

**실제 예시 — 학생**: ‘통합사회 2단원 시험 대비’ 노트북에 수업 슬라이드·학습지 PDF·내 필기(OneNote)를 넣는다 → 학습 가이드의 플래시카드로 매일 10분 복습 → 시험 전날 퀴즈로 점검 → 틀린 주제는 “이 개념을 예시로 다시 설명해 줘”라고 채팅.

**실제 예시 — 교사**: ‘우리 학교 교육과정 지식방’ 노트북에 학교 교육과정 편성표·학업성적관리규정·평가 계획을 넣는다(학생 개인정보 없는 문서만) → “3학년 선택과목 개설 조건은?”, “수행평가 반영 비율 규정 조항”처럼 질문 → 근거 문서에 연결된 답. 마인드맵으로 신규 교사 안내 자료도 만든다.

**수업 운영 팁**: 교사가 단원 자료를 넣은 노트북을 만들어 학급과 공유해도, 플래시카드·퀴즈는 학생이 각자 생성해야 한다. 모둠별로 서로의 플래시카드로 문제를 내는 활동으로 연결하면 좋다.

### ④ Learning Zone — 학생이 눌러 보며 배우는 인터랙티브 레슨

설명을 입력하면 **내용 슬라이드와 연습 문제가 섞인 레슨**을 만들고, 학생에게 내준 뒤 누가 어디서 막혔는지 리포트로 본다. Windows 앱이며 교육용 A1·A3·A5에 포함된다([Microsoft 지원](https://support.microsoft.com/en-us/education/getting-started-with-microsoft-learning-zone), [learningzone.microsoft.com](https://learningzone.microsoft.com/)).

**레슨 만들고 내주기 흐름**

1. 새 레슨 → 레슨 설명 입력, 성취기준·학년·활동 유형·언어·슬라이드 수 설정, ‘레슨 균형’ 슬라이더로 설명:연습 비율 조절.
2. AI가 레슨 개요를 먼저 만든다 → 교사가 항목을 고치거나 순서를 바꾼다.
3. 레슨 생성 → 슬라이드가 하나씩 만들어진다. 검토하지 않은 AI 슬라이드에는 **보라색 점**이 붙어, 모두 확인하기 전에는 공유 전 알림이 뜬다.
4. 슬라이드 다시 생성·문장 쉽게 하기·이미지 추가 → ‘학생 보기’로 직접 풀어 본다.
5. 공유: 짧은 코드, 링크, Teams 과제, LMS. 교사가 화면을 이끄는 실시간 수업 모드도 있다.
6. 리포트 탭: 과제별 참여 인원·평균, 학생·문항별로 어려워한 곳을 확인.

**쓰기 전에 꼭 알아야 할 제약**

| 항목 | 현재 상태(발표 기준) |
| --- | --- |
| 레슨 생성 기기 | Copilot+ PC. 일반 Windows 11 PC도 2027-08-01까지 생성 가능(1회 최대 10슬라이드) |
| 레슨 생성 언어 | **영어·스페인어**·프랑스어·이탈리아어·일본어·포르투갈어(브라질). 한국어는 현재 목록에 없음 |
| 앱 화면 언어 | 50개 이상(한국어 화면 사용 가능성) |
| AI 없이 쓸 수 있는 것 | 파트너 레슨 라이브러리, 과제 배포, 리포트 |

**실제 예시 — 영어 수업(생성 언어 제약에 맞춘 추천)**: “High school grade 10, reading lesson on climate change vocabulary, 10 slides, include matching and short-answer practice” → 개요 확인 → 생성 → 보라점 슬라이드 검토 → 짧은 코드로 학생에게 공유 → 리포트에서 오답이 많은 어휘를 다음 수업 도입에 반영.

**다른 교과는**: 한국어 생성이 지원되지 않으므로 ① 파트너 레슨 라이브러리에서 고르거나 ② 빈 레슨에 직접 슬라이드·문항을 넣고 배포·리포트 기능만 쓴다.

**접속 방법**

1. PENZ에 교육디지털원패스로 로그인한 뒤 Microsoft 365를 연다. 또는 m365.cloud.microsoft(Microsoft 365 Copilot 앱)에 **PENZ 계정**으로 로그인한다. 개인 Microsoft 계정이 아니다.
2. Copilot 화면에 방패(데이터 보호) 표시가 있는지 확인한다. 있으면 입력 내용이 학습에 쓰이지 않는 학교 계정 상태다.
3. 교사는 앱 왼쪽에서 Teach, 학생은 Notebooks·에이전트를 찾는다(메뉴 이름·위치는 업데이트로 바뀔 수 있음).
4. 내 라이선스 확인: myaccount.microsoft.com → 구독. “Microsoft 365 Copilot”이 보이면 워드·엑셀·파워포인트 안 Copilot까지, A1·A3 등만 보이면 Copilot Chat까지다.

**교사 활용 — 바로 해 볼 4가지**

| 하고 싶은 일 | 도구 | 이렇게 요청 |
| --- | --- | --- |
| 단원 수업 계획 | Teach → 수업 계획 / 단원 계획 | “고1 통합과학 기후변화 단원 4차시, 활동 중심, 성취기준 포함” |
| 자료 수준 맞추기 | Teach → 콘텐츠 수정 | 읽기 자료를 올리고 “기초 학력 학생용으로 쉽게, 어휘 풀이 포함” |
| 형성평가·루브릭 | Teach → 퀴즈 / 루브릭 | “문항 5개, 오답 해설 포함” → Forms·Teams 과제로 연결 |
| 단원 자료 지식방 | Copilot Notebooks | 교육과정·교재·워크시트를 모아 “이 자료 안에서만 답해” |

**학생 활용 — 수업 안에서**

| --- | --- | --- | --- |

| 개념이 막힐 때 | Study and Learn 에이전트 | 답 대신 힌트·질문으로 이해 | 대화 기록을 성찰지로 제출 |
| 글쓰기 피드백 | Copilot Chat | 초안을 올리고 “논리 빈틈만 지적, 고쳐 쓰지 마” | AI 사용 표시 규칙 |
| 조사 활동 | Copilot Chat(웹 검색) | 답변의 출처 링크를 열어 직접 확인 | 출처와 내용 일치 여부 |

**ChatGPT와 어떻게 나눠 쓸까**

|  | Microsoft Copilot(에듀) | ChatGPT |
| --- | --- | --- |
| 비용 | PENZ 계정으로 무료(Chat·Teach·Notebooks) | 무료 + 유료 기능(Work·Sites·스킬) |

**관리자(학교·교육청 정보 담당)에게 미리 확인**
